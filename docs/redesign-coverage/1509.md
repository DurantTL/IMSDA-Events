# Coverage: #1509 part 2, prices by attendee type and staff price override

Rows for the #1596 coverage ledger (see `docs/REDESIGN-RELEASE-1.md`). Part 1 (price windows) shipped in #1938. Pricing changes on real events stay a human step: these are tools only, every new option is off, existing forms price exactly as before, and no seeded or live price changed.

| Page | Issue | Where it lives | What changed | Browser check (1280 / 390) | Not checked, and why |
|---|---|---|---|---|---|
| `/registration-builder` (question settings) | #1509 | A per-person question, Advanced options, under "Use a different price starting on a date" | "Charge a different price for each type of attendee" (off by default; only on a per-person question that is not a choice, credit, information, signature or acknowledgment, and only when the form has an attendee-type question). On, it lists each active attendee type with a price box for the starting price and one for each price window. A blank box charges the usual price. Turning it off clears every price it holds | To be run by review | |
| `/finance` (Adjust modal) | #1509 | Finance, a registration, "Adjust" | New type "Set this person's price": choose one person, see their current price, enter the new price and a reason. The total moves by the difference, never below $0 or below what was paid. It shows in the adjustment list as "Price override" and can be reversed like other adjustments | To be run by review | |

Operations notes:

- Migration `20270186100000_staff_price_override` only adds two enum values (adjustment kind and ledger source type). Applying it in production is a human step.
- Money readers: event info cards list one fee line per type ("Fee - Child") plus "any other type" when the question also has a usual price; the church invoice sentence is left out for a type-priced fee, since no single per-person rate is true. Per-person prices on invoices and totals come from the line items, which already carry each person's own amount.
- The event money report's "scholarships and discounts" counts do not include price overrides; they appear in the registration's adjustment list and the ledger.
