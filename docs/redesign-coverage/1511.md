# Redesign coverage: #1511 saved views of the Registrations list (first slice)

Rows for the #1596 coverage ledger (see `docs/REDESIGN-RELEASE-1.md`). First slice only: saving the current filters as a personal view, sharing a view with event staff, and telling people when a saved view uses a filter that no longer exists or that they cannot use. Dashboard counts that open filtered lists are a later slice.

| Page | Issue | Where it lives | What changed | Browser check (1280 / 390) | Not checked, and why |
|---|---|---|---|---|---|
| `/people` (Saved views panel) | #1511 | Event → Registrations → All registrations, under the search | A "Saved views" panel under the search lists "Your views" and "Shared with event staff" (with "Shared by <name>"). Each view is a link back to the list with its filters; the one that matches the current filters is marked "Showing now". With filters or a sort chosen, "Save these filters" takes a name, and staff who can manage registrations also get "Share with event staff". Owners can Share or Stop sharing, and Delete with a confirm (someone who manages registrations can also delete another person's shared view). A view that uses a filter that no longer exists, or one the viewer cannot use, says so and can still be opened or deleted. A view stores filter keys and values only, never registrations or counts | To be run by review | |

Later decisions (Caleb): a view that uses a deactivated tag counts as no longer existing, so it carries the same note, and saving or sharing one is refused (the search itself still accepts deactivated tags). A shared view made by someone who has since left the event's staff (no active membership, and not a system administrator) is archived: hidden from "Shared with event staff", kept, and shown only to staff who can share, in a collapsed "Archived views" group with Restore (the restorer becomes the owner and it stays shared) and Delete. No schema change; the state is worked out when the list loads.
