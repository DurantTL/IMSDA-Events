The shared list parts: sortable column headers, the "Showing 1–25 of 140" pager, and tables that become cards on a phone.

- A sortable header is a `th` holding a `.table-sort-button` (a link on server-sorted lists, a button on lists sorted in the browser) with a 13px arrow: up or down on the sorted column, a two-way arrow on the others. The `th` carries `aria-sort`; the sorted column turns navy and bold. `.sort-order-note` says the order in words ("Sorted by club name, A to Z."); `.sort-order-row` puts it beside other tools.
- `.list-pager` shows the count line in `.quiet-copy`; with more than one page it also shows Previous, "Page 1 of 6" and Next as `.secondary-button` in `.list-pager-buttons` (44px; an unavailable end is `aria-disabled` at 58% opacity). One page shows only the count line.
- A `table.table-cards` inside a wrap (`.report-table-wrap`, `.table-wrap`, `.table-scroll`, `.reminder-recipient-table-wrap` or `.card-box`) turns into one bordered card per row when the wrap's own width is too narrow, not when the screen is. Variants (`table-cards-tablet`, `-wide`, `-xwide`, `-max`, `-huge`) set the width where it switches (600, 760, 860, 1100, 1260 and 1380px).
- In a card the row header (`th scope="row"`) is the card title; each `td` carries `data-label` and reads "Header: value"; a cell without a label (the row action) sits at the bottom above a thin line. The header row is hidden, except that sortable headers stay on screen as a "Sort by" row of buttons above the cards.
- Mark cells with `cardCell("Header")` so the label and ARIA roles come along; a table without a wrap never becomes cards.
- Every staff list uses the same pager wording and sort headers (rules B1 and B3); see `ReportTable` for the table itself.
