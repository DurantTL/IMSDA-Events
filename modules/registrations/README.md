# Registrations module

Owns registration containers and attendee participation records. It must support individual, household, group, worker, and imported paths without requiring a club relationship.

`Registration.submittedAt` is the nullable, server-written timestamp of the original successful submission. Staff lists sort by it on the server, with unknown historical values last, and edits, transfers, resends, and later payments leave it unchanged. Admin screens render submitted and last-updated timestamps in the event's configured IANA timezone and name that timezone; CSV exports retain the canonical UTC ISO 8601 value. Historical registrations remain null unless a trustworthy source timestamp is available.

Public form submissions create a normal `Registration`, an ordered attendee party, and a one-to-one `PublicRegistrationSubmission`. The submission stores the exact published version, sanitized registration/attendee responses, request hash/idempotency key, and immutable server pricing snapshot. Capacity-aware answers create normalized `RegistrationCapacityReservation` rows in the same serializable transaction. Anonymous submissions may reuse an existing person by normalized email but never overwrite that person’s canonical profile; event-specific contact details remain in registration and attendee snapshots.

Explicit lifecycle operations own cancellation, reactivation, waitlist entry, manual promotion, and automatic earliest-fitting promotion. They release or restore capacity atomically, preserve totals, maintain queue positions, write audit history, and queue transactional notices. Staff edits cannot bypass status transitions. Expiring hash-only private links expose contact and tiered low-risk answer self-service plus read-only attendees, status, payment history, and Square checkout. An enumeration-safe, rate-limited recovery request can issue a fresh link only when the confirmation code and current registration contact email match.

Authorized staff can use a two-step review to transfer an entire registration to a new account holder or substitute one attendee in place. Both operations require a client UUID, run in a serializable transaction, persist immutable before/after snapshots, and return the exact stored response on a same-input retry. A transfer changes only the account holder and contact snapshot: the registration, party, answers, order, totals, payments, refunds, promo redemption, capacity reservations, and waitlist state keep their existing identities and values. It revokes active management links in the transaction and issues the replacement contact's deterministic private access only after commit.

An attendee substitution updates the existing attendee row's person and profile snapshot without changing its ID, position, attendee type, form responses, pricing, or capacity claims. A checked-in attendee cannot be substituted until staff undo the active check-in, and the replacement cannot duplicate another person already in the party. Both workflows write a separate audit record and queue versioned notices without storing or logging raw access tokens. They remain staff-only; the private public workflow does not expose transfer, substitution, cancellation, or refund controls.

## Operations search (#180)

`operations-search-domain.ts` (pure) and `operations-search-repository.ts` (database) are the one event-scoped search and filter service for staff lists. The People list uses it when the URL carries a structured filter, a sort or a page; the reviewed audience builder (#176) reads the same definition of who matches (`enumerateOperationsRegistrationIds` returns every matching id, bounded at `MAX_PAGE` x `MAX_PAGE_SIZE`, with the same predicate and permission checks). It extends `search.ts` rather than replacing it: text still finds a registration by its code, its account holder or any attendee on it, and every word must match the same person.

- **One predicate.** `buildRegistrationWhere` is the only place a `where` is built. Rows, the total, the status facets and the autocomplete suggestions all start from `prepare()` in the repository, so a count can never describe a different set than the rows beside it. Reads run in one repeatable-read transaction with a statement timeout.
- **Stable keys.** Filter keys (`FILTER_KEYS`) and values are fixed identifiers: attendee-type codes, tag ids, location ids, and form answers named `answer=<SCOPE>:<field key>=<stored value>`, never a label. A version change or relabel keeps the meaning. A key or value the form no longer offers returns an issue (`field-unavailable`, `value-not-offered`, `stale-reference`) and no rows; it is never read as something else.
- **Permission per domain.** `DOMAIN_PERMISSIONS` maps each domain (lifecycle, identity, payment, check-in, tags, form answers) to the permissions that unlock it. A filter the viewer may not use is refused with the same `unavailable` issue as one the event does not have, before any query runs, and a domain the viewer may not use is not even loaded. A sensitive or health-type form question is never offered to anyone.
- **Never searchable.** Staff note bodies (restricted or not), consent evidence, health and medical data, and event membership have no filter key and are not in the predicate. Another event is unreachable: the viewer is built for one event and every query starts with its id.
- **Canonical order and paging.** Sort keys are `submitted` (default), `created`, `code`, `name`, `total`; every order ends with created time and then id in the same direction, so ties page without gaps or repeats. Page size is capped at 100 and depth at 200 pages; text is capped at 100 characters and six words. A money-state filter resolves in SQL over one event's payments and is refused as too broad past 20,000 registrations.
- **URL form.** `serializeOperationsSearchQuery` produces one canonical query string (fixed order, sorted values, defaults omitted) that `parseOperationsSearchParams` reads back to the same query, suitable for a link now and a saved view later.

The service returns registration ids, not rows: each list loads the page it shows with its own permission-gated loader.
